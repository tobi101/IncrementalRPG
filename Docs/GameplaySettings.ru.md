## 2. Дерево прокачки

Файлы: [общий конфиг дерева](/Users/admin/IncrementalRPG/Assets/SO/SkillTree/SkillTreeConfig.asset), [ноды](/Users/admin/IncrementalRPG/Assets/SO/SkillTree/Nodes). ### Поля одной ноды

| Поле | Что меняет |
|---|---|
| `id` | Уникальный ключ ноды в сохранении. Не повторять у двух нод |
| `displayName`, `description` | Локализованные название и описание в окне ноды |
| `icon`, `additionalIcon` | Основная и дополнительная маленькая иконки |
| `maxLevel` | Количество покупок ноды, минимум 1 |
| `goldCostPerLevel` | Цена каждой очередной покупки. Элемент 0 — переход 0→1, элемент 1 — 1→2 |
| `prerequisites[].node` | Предыдущая нода |
| `prerequisites[].requiredLevel` | Сколько уровней предыдущей ноды нужно купить. Для покупки должны выполняться **все** зависимости |
| `effects` | Один или несколько эффектов покупки |
| `effects[].effectType` | `Additive`, `Multiplicative` или `FeatureUnlock` |
| `effects[].statType` | Изменяемая характеристика, таблица ниже |
| `effects[].valuesPerLevel` | **Прибавка за каждую покупку**, а не итог на этом уровне. Индекс 0 соответствует первой покупке |
| `effects[].feature` | Открываемая механика для `FeatureUnlock`; у двух других типов игнорируется |

Заполняйте цену и значения эффекта на все `maxLevel` уровней. Отсутствующая или некорректная цена блокирует покупку; для бесплатного уровня явно задайте 0. Недостающий элемент эффекта не даёт прибавки. Лишние элементы за пределами `maxLevel` не участвуют.

Skills и классы используют общее ядро `SkillTreeProgression` и базовые данные `SkillNodeDefinition`. Уровни и правила показа у деревьев отдельные, кошелёк золота общий. В `SkillTreeView` настройка `Show Connections` отключает только линии; требования к предыдущим нодам продолжают действовать.

`Additive` складывает значения купленных уровней в сумму **A**. `Multiplicative` тоже сначала складывает доли в **P**, затем даёт множитель **1 + P**. Два бонуса `0.1` дают множитель `1.2`, а не `1.21`. Название типа эффекта не гарантирует, что выбранная характеристика его использует: ниже перечислены реально подключённые варианты.

### Все характеристики дерева и реальные формулы

Обозначения: **B** — базовое значение; **A** — сумма `Additive`; **P** — сумма `Multiplicative`. Отрицательные/слишком маленькие результаты некоторые потребители ограничивают; допустимые рабочие значения приведены в описаниях.

| `StatType` | Рабочие типы эффектов | Результат и единицы |
|---|---|---|
| `ManualAttackDamage` | Additive + Multiplicative | `(B + A) × (1 + P)`, урон ручного удара; результат округляется |
| `AutoAttackDamage` | Additive + Multiplicative | `(B + A) × (1 + P)`; дробный урон сохраняется и снимает дробное HP |
| `SpecialAttackDamage` | Additive + Multiplicative | Та же формула для особой атаки |
| `ManualAttackSpeed` | Additive + Multiplicative | Интервал = `max(0.05, max(0.05, B) / max(0.01, (1 + A) × (1 + P)))`, с |
| `AutoAttackSpeed` | Additive + Multiplicative | Та же формула для периода автоатаки |
| `ZoneRadius` | **Multiplicative** | Горизонтальный радиус = `B × (1 + P)`; Additive здесь не читается |
| `SpawnSpeed` | **Additive** | Интервал = `max(B × (1 − A), minSpawnInterval)`; `0.1` уменьшает исходный интервал на 10% |
| `MapSize` | **Additive** | Сторона квадратной сетки = `minPlayZoneSize + (int)A`; дробная часть отбрасывается |
| `SessionTime` | **Additive** | Дополнительные секунды к времени уровня |
| `BombExplosionRadius` | Additive + Multiplicative | `B × (1 + P) + A`, мировые единицы; абсолютная прибавка применяется после множителя |
| `BombExplosionDamage` | Additive + Multiplicative | `(B + A) × (1 + P)`, целый урон взрыва |
| `BombSpawnSpeed` | **Additive** | `max(B × (1 − A), minBombSpawnInterval)`; отдельный таймер бочек |
| `GoldDrop` | **Multiplicative** | Золото существа × `goldDropMultiplier` уровня × `(1 + P)`, с округлением |
| `InitialEnemySpawnDensity` | **Additive** | Прибавка к доле клеток, заполняемых обычными существами при старте |
| `InitialBombSpawnDensity` | **Additive** | Прибавка к доле клеток для стартовых бочек |
| `SlimeShardDrop` | **Multiplicative** | Базовые осколки слизня × `(1 + P)`, с округлением |
| `SkeletonShardDrop` | **Multiplicative** | Аналогично для скелета |
| `DemonShardDrop` | **Multiplicative** | Аналогично для демона |
| `CrystalShardDropBonus` | **Additive** | Абсолютная прибавка к осколкам кристалла |
| `ShardPickupSpeed` | Additive + Multiplicative | Время сбора = `max(0.01, B / max(0.01, (1 + A) × (1 + P)))`, с |

Неперечисленный для строки тип эффекта не используется этой механикой, даже если его можно выбрать в Inspector. Например, процентный радиус зоны задаётся через `Multiplicative`, а уменьшение интервала спавна — через `Additive` с долями.

`FeatureUnlock` открывает `Bombs`, `AutoAttack`, `SpecialAttack` или `Shards` после первой покупки. `None` не открывает игровую механику. У ручной атаки отдельный unlock не требуется. Скорость особой атаки отдельным `StatType` пока не представлена: её задержка меняется в базовом конфиге.

### Положение, связи и видимость

| Поле общего конфига | Назначение |
|---|---|
| `entries[].node` | Нода, включённая в активное дерево |
| `entries[].gridPosition` | Целочисленные X/Y на сетке |
| `cellSpacing` | Расстояние между клетками по X/Y в UI; сейчас 150×150 |
| `origin` | Смещение начала координат |

Линии строятся по `prerequisites`, а положение — по `entries`. Старое скрытое поле `positionInGraph` не управляет текущим деревом при заполненных `entries`.

До первой покупки видна стартовая нода. Далее видимость смотрит на **первую** зависимость и её первую зависимость: если в родителя или такого прародителя вложен хотя бы один уровень, нода видна. Поэтому показываются следующие ноды и ещё слой заблокированного продолжения. Для покупки учитываются **все** родители и их `requiredLevel`.

Полная прокачка — зелёная, доступная покупка — жёлтая, нехватка золота — красная; заблокированные требования имеют отдельное состояние `Locked` и анимацию замка. Конкретные цвета/спрайты задаются в `ViewConfigs`, анимация раскрытия — в `SkillTreeView` (руководство аниматора).

Существующие ноды урона усиливают ручную атаку. Отдельные характеристики авто/особой атаки уже поддерживаются, но отдельные ноды их урона в текущем дереве не размещены. Для новой ноды достаточно конфига с соответствующим `StatType` и записи в `entries`.

Три ноды частоты спавна размещены после `AddZoneDamageNode 3`: координаты (10,3), (12,3), (14,3). Первая требует 5 уровней этой ноды урона; последующие требуют по 1 уровню своей предыдущей ноды. Имена файлов в цепочке: `AddSpawnSpeedNode` → `AddSpawnSpeedNode 2` → `AddSpawnSpeedNode 1`.

### Пример настройки

Нужно +10% ручного урона за каждую из трёх покупок: `maxLevel = 3`, три цены, эффект `Multiplicative`, характеристика `ManualAttackDamage`, массив `0.1, 0.1, 0.1`. Итог после третьей покупки — +30% к базе с абсолютными прибавками. Для автоатаки поменяйте только характеристику на `AutoAttackDamage`.

Текущая формула времени уровня:

`100 / max(heatIndex, 0.0001) − ArmorIndex / 2.5 + Additive(SessionTime)` секунд.

Знак перед бронёй в реализации **минус**. `ArmorIndex` пока берётся из состояния игрока, а не из экипированных предметов. Его начальное значение 1 задано в коде. Это описание текущей формулы, а не рекомендация баланса.

При достижении `xpGoal` работает окно добора осколков `lootGraceDuration`, затем переход. На последнем доступном уровне показывается предусмотренный игрой экран окончания демо; отдельного числового «лимита демо» в конфиге нет. Порядок и наличие пригодных уровней определяются массивом `levels`.

## 5. Спавн врагов, кристаллов и бочек

Таблица спавна — asset типа `SpawnTable`, назначенный именно в нужном уровне. В биоме есть несколько файлов `0_*SpawnRule`: ориентируйтесь на ссылку `spawnTable`, а не только на имя файла.

| Поле записи таблицы | Назначение |
|---|---|
| `entries[].config` | `EntityConfig` существа/бочки/кристалла |
| `entries[].weight` | Относительная вероятность среди подходящих записей; нулевой вес исключает запись |
| `entries[].requiredFeature` | Требуемая разблокировка дерева; `None` — без требования |

Шанс конкретной подходящей записи = её вес / сумма весов подходящих записей. Веса не обязаны суммироваться до 100.

**Общий периодический спавн** выбирает из всех подходящих записей, кроме `FeatureType.Bomb`: это обычные враги и, если разрешены таблицей, кристаллы. Поэтому характеристика `SpawnSpeed` сейчас ускоряет общий поток без бочек, а не отдельный таймер каждого вида врага.

**Бочки** имеют отдельный период и требуют открытия `Bombs`. Дополнительной проверки шанса бочки после таймера нет. Но нужны свободная клетка и подходящая запись бочки в таблице. Веса нескольких бочек выбирают вариант бочки, а не вероятность пропуска появления. Первое периодическое появление ждёт интервал; немедленные стартовые бочки задаются плотностью.

Начальное заполнение: `round(число клеток × max(0, плотность уровня + A))`. Обычная стартовая плотность выбирает `FeatureType.None`; стартовые бочки — `FeatureType.Bomb`. Это одноразовое заполнение при старте, а не частота дальнейшего появления. Карта ограничивает число реально размещаемых объектов.

Базовый период — задержка до прокачки. Минимальный — нижний предел после прокачки. Пример: база 2 с, минимум 0,5 с, сумма `SpawnSpeed = 0.25` → итог 1,5 с. Если минимум равен базе или выше неё, бонус не ускоряет спавн. В текущих пяти уровнях RocksAndLava такой предел уже достигнут; значения приведены в каталоге как факт текущей настройки.

У новых полей интервала бочек исходные значения в классе — 10 с и 0,5 с. В существующих YAML уровней эти поля на момент документации ещё не записаны явно. Проверяйте значение в Inspector перед изменением и сохранением конкретного уровня.

`entityKind` и `featureType` решают разные задачи. Для бочки HP берётся из её `EntityConfig`, а урон взрыва — из `BombExplosionConfig`. `moveSpeed` перемещает объект и не ускоряет Spine-клип ходьбы автоматически.

`countsAsEnemyKill` влияет на золото и опыт через событие `OnEnemyKilled`. Система осколков слушает уничтожение сущности отдельно и дополнительно проверяет вид/разблокировку. Поэтому не стоит считать этот флаг общим выключателем всех наград.

### Экипировка: семь процентных характеристик

Настройка: `ItemDefinition → Armor → Default Stats`. В `Stat Id` выбирается значение из списка, в `Value` вводится доля бонуса (`0.10` = +10%). Допустимые ID заданы в [EquipmentStats.cs](/Users/admin/IncrementalRPG/Assets/Scripts/Core/Items/EquipmentStats.cs). Неизвестные ID, повтор одного ID внутри предмета, отрицательные и неконечные значения недопустимы: Inspector сообщает ошибку настройки, создание и экипировка такой брони отклоняются.

| Stat Id | Действие после тренировки |
|---|---|
| `manual_attack_damage` | Урон только ручной атаки × (1 + сумма бонусов) |
| `auto_attack_damage` | Урон только автоатаки × (1 + сумма бонусов) |
| `manual_attack_speed` | Интервал ручной атаки / (1 + сумма бонусов) |
| `auto_attack_speed` | Интервал автоатаки / (1 + сумма бонусов) |
| `player_zone_radius` | Радиус зоны × (1 + сумма бонусов); обе оси и визуальный круг |
| `barrel_explosion_damage` | Урон взрыва бочки × (1 + сумма бонусов) |
| `barrel_explosion_radius` | Радиус взрыва × (1 + сумма бонусов); область поражения и визуальный масштаб |

Бонусы одинаковой характеристики на **надетых** шлеме, нагруднике и оружии складываются; одновременно действует по одному предмету каждого слота. Для урона ручной и автоматической атак: `(база + плоская прибавка тренировки) × множитель тренировки × (1 + сумма экипировки) × множитель зелья`. Ручной урон затем округляется до целого, автоматический сохраняет дробную часть. Пример: урон после тренировки 100, два предмета по +10% → 120, ярость +25% → 150. База автоатаки 1 и прибавка ноды 0,25 дают удар на 1,25: у врага с 5 HP остаётся 3,75 HP, четыре удара убивают его. Превью ноды, статистика и всплывающий урон показывают до двух знаков после запятой. Особая атака не получает ни урона, ни скорости от этих семи бонусов, но на неё действуют зелья ярости и концентрации. Ярость не усиливает взрыв бочки.

Надетый предмет освобождает занимаемые ячейки и отображается только в слоте экипировки. Экземпляр остаётся в общем сохранённом хранилище `PlayerItemStorage.Items`; `InventoryItems` содержит только предметы сумки. Надетый экземпляр имеет `AnchorIndex = -1`, а ссылка соответствующего слота отличает его от ожидающего размещения лута. При снятии по ПКМ ищется свободное место под весь размер предмета; если его нет, предмет остаётся надетым и появляется сообщение. Надетый предмет также можно перетащить из слота героя в выбранные свободные ячейки сумки. До успешного размещения он остаётся надетым и продолжает давать бонусы. Занятые ячейки, выход размера за край, отмена, бросок вне сетки и закрытие инвентаря отменяют перенос без изменения сохранения. Непосредственное перетаскивание надетого предмета в печь не перерабатывает его: сначала его нужно снять в сумку. При замене сначала учитываются освобождаемые ячейки нового предмета и проверяется место для старого, затем обе позиции меняются одновременно. Это позволяет менять снаряжение того же типа даже при полной сумке. Геометрия берётся из топологии игрового инвентаря. После перетаскивания сетка перестраивается, когда менеджер перетаскивания завершил операцию. При загрузке старого сохранения позиции уже надетых предметов очищаются один раз; их характеристики, образы и ссылки экипировки сохраняются.

Частоты ручной и автоматической атак независимы. Итоговый интервал: `max(0.05, max(0.05, база) / скорость тренировки / (1 + сумма бонусов скорости))`. База ручной атаки — `baseManualAttackCooldown = 0.75 с` в [DamageZoneConfig.asset](/Users/admin/IncrementalRPG/Assets/SO/DamageZone/DamageZoneConfig.asset:18). Нижний предел 0.05 с задан в коде `DamageZone.MinAttackInterval`. Бонус радиуса относится к радиусу, а не площади.

Визуальные настройки и локализация — [интерфейс экипировки](/Users/admin/IncrementalRPG/Docs/PresentationSettings.ru.md#equipment-inventory).

### Зелья: настройки, формулы и применение

В Inspector нужного `ItemDefinition` откройте секцию **Consumable → Effect Value** (`effectValue`). Число задаётся долей: `0.25` = 25%, `0.5` = 50%, `0.2` = 20%. Ввод `25` означает 2500%. Ниже указаны текущие значения ассетов.

| Зелье / конфиг | `itemId` | `effectId` — семейство | `effectValue` | Действие |

| [Большое богатства](/Users/admin/IncrementalRPG/Assets/SO/Items/LargeWealthPotion.asset:49) | `potion_wealth_large` | `creature_gold_bonus` | `0.5` | +50% золота с существ |
| [Ярости](/Users/admin/IncrementalRPG/Assets/SO/Items/RagePotion.asset:49) | `potion_rage` | `player_attack_damage_bonus` | `0.25` | +25% урона ручной, автоматической и особой атак |
| [Большое ярости](/Users/admin/IncrementalRPG/Assets/SO/Items/LargeRagePotion.asset:49) | `potion_rage_large` | `player_attack_damage_bonus` | `0.5` | +50% урона тех же трёх атак |
| [Концентрации](/Users/admin/IncrementalRPG/Assets/SO/Items/ConcentrationPotion.asset:49) | `potion_concentration` | `special_attack_cooldown_reduction` | `0.2` | Время перезарядки особой атаки на 20% короче |

**Формулы.** Золото, ручной и особый урон округляются до целого после всех множителей; автоматический урон сохраняет дробную часть:

- Богатство: `goldDrop существа × max(0, goldDropMultiplier уровня × множитель GoldDrop дерева) × (1 + effectValue)`. Продажа предметов/переработка, осколки и другие источники дохода не меняются.
- Ярость: `урон соответствующей атаки после тренировки и экипировки × (1 + effectValue)`. Каждый из трёх видов атак использует собственную базу и характеристику тренировки; экипировка усиливает только ручную и автоматическую атаки. Урон взрыва бочки не меняется.
- Концентрация: `max(0, baseSpecialAttackCooldown) × (1 − effectValue)`. Хранится **доля сокращения длительности**, а не скорость восстановления: 10 с при `0.2` становятся 8 с, не `10 / 1.2`. Ручная и автоматическая атаки не ускоряются. Зелье не открывает особую атаку, если она ещё не изучена.

Для богатства и ярости задавайте конечное неотрицательное число. Для концентрации допустимо `0 ≤ effectValue < 1`. Inspector не ограничивает `effectValue`, но недопустимое значение или неизвестный `effectId` блокируют применение без списания предмета. Уже подготовленный эффект сохраняет свою силу, даже если позже изменить конфиг.

Снимок исходных семи листов и параметры игры: [ForgeBalance.data.json](/Users/admin/IncrementalRPG/Docs/ForgeBalance.data.json). По подтверждению пользователя от 18 октября 2026 года бюджет уникального предмета изменён с 135% на 136%, чтобы каждый бонус оставался кратным 2%. Лист классовых статов и ставка их продажи не применяются: классы исключены из текущего объёма.

В `levels[]` настраиваются `shardCost`, четыре `rarityWeights`, четыре `statBudgets`, `cursorPeriod` и диапазоны QTE. Веса относительные, конечные и неотрицательные; хотя бы один положительный. Цена — положительное целое. Диапазоны задают **полную ширину** симметричной зоны по центру шкалы: `rarityRange ≤ allStatsRange ≤ oneStatRange ≤ 1`. Например, 0.02 занимает 2% всей шкалы. За пределами `oneStatRange` усиления нет. Таблица задаёт размеры вложенных зон; их нельзя складывать как независимые вероятности.

`statBudgets` задаёт общий бюджет бонусов: Common 50%, Rare 100%, Unique 136%, Legendary 200% на всех четырёх уровнях. Количество характеристик — 2 / 3 / 4 / 5. Генератор случайно распределяет бюджет с минимальным бонусом 2% и шагом 2%. Состав выбирается без повторов из семи существующих обычных характеристик экипировки; классовые бонусы не генерируются. Кузница отклоняет нечётный бюджет и бюджет, которого не хватает на минимальные бонусы.

`oneStatBonus = 0.15` усиливает один случайный бонус на 15%; `allStatsBonus = 0.10` — все бонусы на 10%. Свиток усиления даёт 5%. После усилений каждый новый бонус округляется к ближайшим 2%, минимум 2%; маленькое усиление может не изменить маленький бонус. Эти величины усилений и скорость ползунка не указаны в таблице, поэтому сохранены прежние настройки проекта.

В центре QTE редкость повышается на одну ступень и добавляется новый случайный обычный стат. Его базовая сила — разность бюджетов новой и старой редкости: 50%, 36% или 64%. Ранее выбранные статы сохраняются; без свитка итоговая сумма соответствует бюджету новой редкости. На добавленный стат также действует свиток усиления. Для уже легендарного предмета идеальное попадание усиливает все статы на `allStatsBonus`, сохраняя легендарную редкость.

`equipment` содержит три базовых определения: [шлем](/Users/admin/IncrementalRPG/Assets/SO/Forge/Forgedhelmet.asset), [нагрудник](/Users/admin/IncrementalRPG/Assets/SO/Forge/Forgedchest.asset), [оружие](/Users/admin/IncrementalRPG/Assets/SO/Forge/Forgedweapon.asset). Без свитка шансы типов равны. Поле `appearanceCatalog` каждого определения ссылается на [EquipmentAppearances](/Users/admin/IncrementalRPG/Assets/SO/Forge/EquipmentAppearances.asset): 36 образов, по три на каждую пару слот/редкость, по пять названий на образ.

**Образ и имя выбираются после QTE по итоговой редкости.** Сначала выбирается один из трёх образов, затем одно из пяти его названий. `PlayerItemInstanceState.AppearanceId` хранит постоянный ID образа, `RolledNameKey` — выбранное имя. Результат ковки, ячейка инвентаря, перенос, подсказка и слот экипировки используют изображение этого экземпляра. Перестановка записей каталога не меняет сохранённый образ.

Редактируемые соответствия: [каталог](/Users/admin/IncrementalRPG/Docs/ItemCatalog.ru.md) и [его данные](/Users/admin/IncrementalRPG/Docs/ItemCatalog.data.json). Все 180 названий заданы на ru-RU, en-US и zh в `LocalesTable`; исходные строки для импорта находятся в [ItemCatalog.localization.json](/Users/admin/IncrementalRPG/Docs/ItemCatalog.localization.json). Команда Unity `Tools → Items → Import Equipment Catalog and Balance` повторно создаёт каталог, обновляет имена и переносит баланс из файлов `Docs`. Периоды ползунка, величины усилений и условие открытия кузницы при повторном импорте сохраняются.

**Старые сохранения.** При загрузке экипировка без `AppearanceId` однократно заменяется аналогами того же слота и редкости из нового каталога. ID экземпляра, размещение предметов сумки и ссылки экипировки сохраняются; надетые предметы освобождают ячейки сетки. Виды и количество записанных бонусов остаются прежними; значения пропорционально приводятся к текущему бюджету редкости — 50 / 100 / 136 / 200%. Каждый бонус получает минимум 2%; округление по наибольшим остаткам сохраняет точную сумму и шаг 2%. При равных остатках приоритет имеет прежний порядок бонусов. Например, старые +2% и +3% у обычного предмета становятся +20% и +30%. Для прототипов без записанных бонусов состав впервые генерируется по текущим правилам.

Аналог и вариант имени выбираются по стабильному хешу ID экземпляра, после сортировки подходящих образов по ID. `AppearanceId` и `RolledNameKey` записываются в сохранение; повторная загрузка, изменение случайного seed и перестановка каталога не меняют результат. Цена пересчитывается по текущей ставке 30 золота за 1%. `SaveService` сразу сохраняет миграцию после загрузки всех сервисов. Предметы, уже имеющие `AppearanceId`, повторно не балансируются: усиления новой ковки сохраняются. Старые массивы имён и иконок больше не используются; базовые определения типов используют новые изображения.

Ранний прототип оружия `test2` также переносится в `forged_weapon` с сохранением ID экземпляра, позиции и экипировки. При отсутствии записанных характеристик используется его исходная редкость Rare и впервые генерируются три бонуса; имеющиеся виды бонусов и сохранённая редкость сохраняются.

У оплаченной старой попытки ковки сохраняются оплата, свиток, позиция ползунка, тайминг и зоны QTE. Неразрешённая попытка получает новый бюджет бонусов и `RulesVersion = 1`; ранее оплаченный свиток усиления применяется к новому бюджету один раз. Образ и имя по-прежнему выбираются после QTE. Уже готовый незабранный результат мигрирует как обычный старый предмет без повторного QTE. Новые попытки сохраняют бюджет дополнительного стата, QTE и ставку продажи при оплате. Перезапуск не требует повторной оплаты.

Свиток редкости задаёт Rare до QTE. Свиток точности добавляет 0.02 к полной ширине центрального диапазона, ограниченной `allStatsRange`. Выбор свитка не расходует предмет; повторное нажатие отменяет выбор. За одну оплаченную попытку расходуется один свиток.

Для начала нужен свободный квадрат 2×2, даже при гарантированном шлеме. Существующие размеры сохранены: шлем 1×1, нагрудник 2×2, оружие 1×2. При нехватке места, шардов или выбранного свитка ресурсы не расходуются. Оплаченная попытка и незабранный результат сохраняются.

`goldPerBonusPercent = 30`: сумма процентов обычных бонусов умножается на 30. Например, базовые 50% стоят 1500 золота, 136% — 4080 золота. Усиления свитка и QTE учитываются. «Взять» переносит готовый экземпляр в инвентарь, «Разбить» начисляет золото; повторно получить результат нельзя. Цена старых предметов обновляется при однократной миграции.
